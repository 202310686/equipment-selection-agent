# 优化过程与典型问题

## 起点

已有 Agent 能执行文件任务，但方案部反馈配单准确率不高。仅检查型号是否存在，不能判断是否选对产品；任务完成率也不能替代业务正确率。

## 系统识别与配套

一个典型错误是将不同无线系统的主机与单元配在一起。产品描述中的宣传用语可能与系统名称相似，因此不能仅凭关键词判断兼容性。

优化方向是先识别系统，再限定候选，并通过同系列配套查询与规则自检核对。修复重点是工具的判断方式，而非任意改写产品原始参数。

## 需求参数

曾出现客户要求高分辨率产品、Agent 选择较低分辨率产品的情况。历史选型习惯与语义相似不能替代硬参数满足。

对可以可靠提取的分辨率、额定功率、路数、尺寸等加入检查，同时区分额定、峰值、桥接和功耗，避免误报迫使模型改错。

## 经验库与常用设备

项目记录记载接入了 511 个历史项目、8266 条人工配单，以及方案部常用设备表。这些规模数字为内部记录摘要，本仓库不包含原始数据。

常用设备的优先级按业务系统应用。曾尝试全局加分，但使部分广播设备排序变差，说明业务经验不能脱离适用范围。

## 自检覆盖

检查包括型号有效性、停单或旧系列、部分配套关系以及部分数字参数。

一个实际教训是：客户表格缺少标准表头时，检查程序未能识别正确列，导致检查失效。后续加入按内容识别列的处理。检查器本身也需要验证，检查结果为空不等于没有错误。

## 大清单处理

将大单处理拆分为草稿生成、模型决策和文件生成，减少重复调查与重复写表。对不确定的行仍需要判断，不能以提速为由将候选第一名直接等同于正确答案。

## 保留的不足

会议、视频类设备选型仍有不稳定表现；常用设备信息不能解释方案部所有取舍。部分任务和设备类别缺少完整评测。规则检查也无法覆盖全部技术与业务约束。
