# 架构与职责

## 项目组成

| 层次 | 作用 |
| --- | --- |
| Hermes Agent 框架 | 提供模型调用、工具执行、技能与记忆等基础能力 |
| 业务技能 | 描述配单、比单、偏离说明及文件输出规则 |
| 产品资料 | 提供型号、参数、在售或停单状态等信息 |
| 经验资料 | 将历史人工配单和常用设备信息用于检索与排序 |
| Python 工具 | 完成系统识别、候选检索、配套查询、文件生成与检查 |
| 自检插件 | 在执行过程中发现输出文件并反馈检查结果，最终阶段提示残留错误 |
| 评测流程 | 对照客户需求和人工成果，记录匹配效果与运行表现 |

这些组成和行为依据项目记录整理，尚未核验实际代码。

## 选型流程

先解析客户清单，再识别所需系统。非主营产品应留空并说明，不能为了填满表格而强行匹配。

在系统及类型范围内检索候选，再参考历史经验、常用设备和规格信息排序。模型结合上下文选择型号，使用配套工具核对主机与单元等关系，最后生成文件并进行规则检查。

参数检查依赖可靠的参数提取。额定功率、峰值功率、桥接功率和功耗等含义不同，抽错参数会造成错误拦截。

## 变更管理

项目记录中采用独立测试环境、基线环境与版本备份。修改先在测试环境验证，再同步生产环境。核心工具设置只读，工具问题通过反馈文件记录后由维护者修改。

技能和记忆可能被 Agent 自行更新，因此还需要快照、审查与撤回机制。工具只读和自学审查是不同层面的控制。
